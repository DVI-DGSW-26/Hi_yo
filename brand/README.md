# Hi_yo 로고

## 파일

원본은 `build.mjs` 하나다. **SVG 를 손으로 고치지 않는다** — `build.mjs` 의 값을 고치고
다시 돌린다. 그래야 여덟 개 변형이 서로 어긋나지 않는다.

```
node brand/build.mjs      # SVG 여덟 개
node brand/export-png.mjs # png/ 아래 PNG (헤드리스 Chrome 사용, 배경 투명)
```

| 파일 | 언제 쓰나 |
|---|---|
| `hiyo-logo.svg` | 기본. 밝은 배경 |
| `hiyo-logo-on-dark.svg` | 어두운 배경. 글자만 흰색이고 그린은 그대로 |
| `hiyo-logo-mono.svg` | 단색. 1도 인쇄·팩스·각인·도장 |
| `hiyo-logo-mono-reverse.svg` | 단색 반전 |
| `hiyo-mark.svg` | 스마일 심볼 단독. 파비콘·로딩·워터마크 |
| `hiyo-mark-mono.svg` / `-reverse` | 심볼 단색 |
| `hiyo-icon.svg` | 앱 아이콘 (512, 그린 바탕 + 흰 `Hi` + 흰 스마일) |

SVG 는 여백 없이 딱 맞게 잘려 있다. 여백은 쓰는 쪽에서 준다 — 아래 규칙을 따른다.

## 색

`packages/tokens/src/colors.ts` 와 **같은 값**을 쓴다. 로고만 다른 그린을 쓰면
앱 헤더의 로고와 그 아래 Primary 버튼이 서로 다른 초록으로 보인다.

| | 값 | 토큰 |
|---|---|---|
| 그린 | `#00C471` | `colors.primary` |
| 검정 | `#191F28` | `colors.textStrong` |
| 흰색 | `#FFFFFF` | `colors.white` |

토큰이 바뀌면 `build.mjs` 위쪽 상수도 같이 바꾸고 다시 빌드한다.

### 대비 (알고 쓸 것)

- 흰 배경 위 그린은 **2.3:1** 이다. WCAG 로고 예외라 로고 자체는 문제없지만,
  이 그린을 **글자에 쓰면 안 된다**. 토큰 주석에 같은 이유가 적혀 있다.
- 앱 아이콘의 흰색 ↔ 그린도 **2.3:1** 이다. `Hi` 를 읽히게 하려는 용도가 아니라
  형태로 알아보게 하는 용도다. 더 또렷하게 해야 하면 흰색 대신 `#191F28`
  (그린 위에서 **7.2:1**) 을 쓴다.

## 여백

로고 사방에 **글자 높이(cap height)의 절반** 이상을 비운다.
가로형 로고 기준으로는 가로폭의 약 13% 다.

## 최소 크기

| | 최소 |
|---|---|
| 가로형 로고 | 가로 96px (인쇄 25mm) |
| 심볼 단독 | 16px |

이보다 작게 쓸 일이 생기면 가로형 대신 심볼을 쓴다.

## 하지 말 것

- 그림자·그라디언트를 얹지 않는다 (`docs/DESIGN_RULES.md` 와 같은 이유다)
- 세로로 늘이거나 눕히지 않는다. 비율을 고정해서 키운다
- 스마일만 다른 색으로 바꾸지 않는다. 색 조합은 위 네 가지가 전부다
- 사진 위에 기본형을 얹지 않는다 — 단색 버전을 쓴다
- 그린이 이미 한 곳 들어간 화면에 로고를 또 올릴 때는
  「한 화면에 그린 2곳 이하」 예산을 로고가 한 자리 먹는다는 것을 센다

## 스마일의 세로 위치

베이스라인에서 **30 올려** 놓았다 (2026-09-11 결정).

0 이면 스마일이 베이스라인 아래에만 있어서 `i` 와 `y` 사이 x-height 구간이 비고,
`Hi yo` 두 단어처럼 읽힌다. 30 올리면 그 구간을 채워 한 단어로 붙는다.
작게 줄일수록 차이가 커진다.

값은 `build.mjs` 의 `SMILE_DY` 하나다. 다르게 보고 싶으면
`SMILE_DY=0 node brand/build.mjs` 로 뽑아 본다 (돌려놓는 것을 잊지 말 것).
심볼 단독(`hiyo-mark.svg`)은 자기 경계에 맞춰 잘려 있어서 이 값과 무관하다.
