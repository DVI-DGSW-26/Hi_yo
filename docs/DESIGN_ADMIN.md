# 관리팀 화면 디자인 규칙

> **상태: 확정 (2026-08-26).** 초안의 결정 항목 4건이 모두 정해졌다 (9장).
> 이 문서에 없는 것은 `DESIGN_SYSTEM.md`를 따른다.

`DESIGN_SYSTEM.md`는 React Native 기준이라 관리팀 화면에 그대로 쓸 수 없다.
이 문서는 **웹에서만 달라지는 것**만 다룬다.

---

## 1. 무엇을 그대로 쓰고 무엇이 다른가

### 그대로 쓴다

- **모든 값은 `@hr/tokens`에서 온다.** CSS에 hex나 여백 숫자를 직접 적지 않는다
  (`src/lib/applyTokens.ts`가 CSS 변수로 심는다)
- 그림자·그라디언트 금지
- 해요체. 느낌표 금지
- 숫자 포맷 — 금액은 세 자리 콤마, 근무시간은 `8시간 20분`
- 로딩·에러·빈 상태 세 가지를 반드시 구현한다

### 다르다

| | 본인용 (모바일) | 관리팀 (웹) |
|---|---|---|
| 한 화면의 정보량 | 한 가지 메시지 | 표 하나에 20열이 넘는다 |
| 입력 | 하루에 한 번 | 하루 종일 |
| 실수의 값 | 내 신청 하나 | 전 직원 급여 |
| 되돌리기 | 다시 신청 | 마감하면 못 되돌린다 |

### 예외 — 관리팀 화면은 `disabled`를 허용한다

모바일은 `disabled`가 없다. 버튼은 항상 눌리고 서버가 막고 그 문구를 보여준다
(`DESIGN_SYSTEM.md` 5장).

**관리팀 화면은 예외다. 업무 상태에 따라 실행 자체가 불가능한 경우가 있기 때문이다** —
마감된 급여 기간에서는 재계산과 금액 수정이 서버에서 막혀 있고, 그건 사용자가 고칠 수 있는
값의 문제가 아니라 기간의 상태다. 눌러보게 두면 매번 같은 오류만 본다.

허용에 붙는 조건 둘이다. 하나라도 못 지키면 `disabled`를 쓰지 않는다.

1. **왜 눌리지 않는지를 버튼 옆에 항상 적는다.** 이유 없는 회색 버튼을 만들지 않는다
2. **서버도 같은 검증을 한다.** 화면에서 막는 것은 두 번째 방어선일 뿐이다

값이 안 채워졌거나 잔여가 부족한 것처럼 **사용자가 고칠 수 있는 이유로는 막지 않는다.**
그건 모바일과 같이 눌리게 두고 인라인 오류로 알린다.

## 2. 화면 틀

```
┌────────┬──────────────────────────────┐
│ 좌측    │ 화면 제목                     │
│ 메뉴    │ ────────────────────────     │
│ 200    │ 도구줄 (필터·기간·실행 버튼)    │
│        │ ────────────────────────     │
│        │ 표 (가로 스크롤)               │
└────────┴──────────────────────────────┘
```

- 좌측 메뉴 `spacing.sideNavWidth`(200) 고정. 본문은 남은 폭을 전부 쓴다. **본문에 최대 너비를 두지 않는다** —
  열이 20개 넘는 표를 가운데 정렬된 좁은 칸에 넣으면 가로 스크롤만 늘어난다
- 최소 지원 폭 **1280px**. 그 아래는 가로 스크롤을 허용한다
- 본문 여백은 `spacing.mainPadY`(36) / `spacing.mainPadX`(32) — 값과 근거는 11장에 있다
- **최대 너비를 두지 않는다는 것은 표 이야기다.** 읽는 문장에는 `readWidth`(620)를 건다 (11장)

---

## 3. 표

관리팀 화면의 본체다. A-601 급여대장은 지급·공제 항목만 20개가 넘는다.

### 뼈대

| | 값 | 근거 |
|---|---|---|
| 행 높이 | `spacing.rowHeight`(44) 최소 | 모바일 `ListRow`와 같은 토큰. 고정하지 않고 `min-height`로 둔다 |
| 헤더 | 배경 `white`, 아래 `borderStrong` 1px | 헤더에 회색 배경을 깔지 않는다. 줄 하나로 구분한다 |
| 행 구분선 | `border` 1px, 가로선만 | **세로선을 긋지 않는다.** 열이 많을수록 격자가 시야를 막는다 |
| 행 hover | 배경 `divider` | 어느 줄을 보고 있는지가 열이 많을수록 중요해진다 |
| 헤더 글자 | `label` / `textWeak` | |
| 본문 글자 | `bodySmall` / `textStrong` | `body`(17)는 표에서 너무 크다 |

### 정렬

- **숫자는 오른쪽.** 금액·일수·시간 전부. `font-variant-numeric: tabular-nums`를 준다.
  자릿수가 흔들리면 합계를 눈으로 못 맞춘다
- 글자는 왼쪽. 상태는 왼쪽
- 헤더 정렬은 셀 정렬과 같게 맞춘다

### 고정

- **헤더는 세로 스크롤에 고정한다** (`position: sticky`)
- **첫 열(직원명)은 가로 스크롤에 고정한다.** 20열을 훑다가 누구 급여인지 잃어버리면 안 된다
- 고정된 열의 경계에만 세로선 하나를 허용한다. 스크롤되는 부분과 구분이 필요하다

### 빈 상태·로딩·에러

표 안에 넣는다. 표를 지우고 다른 것을 그리지 않는다 — 열 머리가 사라지면 무엇을 보던 화면인지 잃는다.

| 상태 | 표기 |
|---|---|
| 로딩 | 헤더는 그대로 두고 본문 자리에 `불러오는 중이에요` |
| 빈 | `아직 계산한 급여가 없어요` 처럼 **무엇이 없는지** 적는다. `데이터 없음` (X) |
| 에러 | 서버가 준 `message`를 그대로. 앱에서 문구를 만들지 않는다 |

### 경고 행

A-601은 "근태 데이터 부족"을 표시해야 하고, 급여 계산은 미확정 근태가 있는 직원을 `skipped`로 돌려준다.

- **경고를 행 배경색으로 칠하지 않는다.** 20열짜리 표가 색으로 얼룩진다
- 해당 셀에 `danger` 글자로 사유를 적는다
- 계산 결과의 `skipped` 명단은 **표 위 도구줄에 건수와 함께 따로 보여준다.**
  성공 개수만 보여주면 급여가 빠진 채로 이체된다

## 4. 폼

A-102는 8개 필드에 검증 규칙이 붙는다.

- 라벨은 필드 **위**에 둔다. 모바일 `TextField`와 같다
- 필수 표시는 라벨 뒤 `*` 하나. 색은 `danger`
- 오류는 필드 **아래** 한 줄, `danger`. 필드 테두리도 `danger`로 바꾼다
- 명세서의 "미입력 필드 하이라이트"는 **테두리 + 아래 문구**로 본다. 배경을 칠하지 않는다
- 읽기전용 필드(직무 선택 시 자동 표시되는 급여대상여부·시급단가)는
  테두리 없이 글자만 둔다. 입력칸처럼 보이면 눌러본다
- 한 화면에 필드가 많으면 2열로 나눈다. 라벨-값 쌍이 가로로 흩어지지 않게 열 폭을 고정한다

## 5. 버튼

모바일 규칙(한 화면에 primary 1개)을 그대로 가져온다. 화면의 주 동작이 무엇인지가
관리팀 화면에서 더 중요하다 — A-601에서 `계산 실행`과 `마감`이 같은 무게로 보이면 안 된다.

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| primary | `primary` 배경, 흰 글자 | 화면의 주 동작 1개 |
| secondary | 흰 배경, `borderStrong` 테두리 | 그 외 |
| danger | 흰 배경, `danger` 테두리·글자 | 아래 기준에 맞는 것만 |

### `danger`는 되돌릴 수 없는 동작에만 쓴다

기준은 하나다 — **되돌리기 어렵거나 업무상 영향이 큰 동작.**

| 쓴다 | 쓰지 않는다 |
|---|---|
| 반려 (신청자에게 즉시 알림, 재신청은 새 건) | 취소·닫기 |
| 퇴사처리 (로그인 비활성화) | 초기화·필터 해제 |
| 급여 기간 마감 (금액 수정이 막힌다) | 목록으로 돌아가기 |
| 삭제 | 저장 |

빨간 버튼이 흔해지면 아무도 안 읽는다. 위 기준에 안 맞으면 secondary다.
`danger`는 **확인 대화상자와 항상 같이 쓴다** (6장).

- 라벨은 동사로 끝낸다. `확인` (X) → `계산 실행하기` (O)
- 표 안의 행별 동작은 버튼을 넣지 않고 **글자 링크**로 둔다. 행마다 버튼이 있으면 표가 버튼 밭이 된다

---

## 6. 확인 대화상자

명세서가 A-102 퇴사처리에 확인 팝업을 명시한다. 되돌릴 수 없는 동작에 쓴다.

- **무엇이 일어나는지 구체적으로 적는다.** `정말 하시겠어요?` (X)
  → `퇴사 처리하면 이 계정으로 로그인할 수 없어요.` (O)
- 좌측 버튼은 `닫기` (`취소` 아님, `DESIGN_SYSTEM.md` 7장)
- 우측이 실행 버튼. 라벨에 동작을 적는다 — `퇴사 처리하기`
- 되돌릴 수 없으면 그 사실을 문구에 적는다. `마감하면 금액을 고칠 수 없어요.`

## 7. 상태 표시

`DESIGN_SYSTEM.md`의 `StatusText`와 같은 원칙이다. **색으로 상태를 구분하려 하지 않는다.**

| tone | 색 | 상태 |
|---|---|---|
| done | `primary` | 확정, 승인, 마감 |
| error | `danger` | 반려, 근태 누락, 계산 제외 |
| neutral | `textWeak` | 그 외 전부 — 대기, 검토중, 계산 전 |

뱃지(알약 배경)를 쓰지 않는다. 표에서 뱃지가 20개 늘어서면 그것만 보인다.

### 그린 예산

한 화면에 `primary`가 등장하는 지점은 **최대 2곳.** 모바일과 같다.

| 화면 | 1곳 | 2곳 |
|---|---|---|
| A-601 급여 | `계산 실행하기` 버튼 | `확정` 상태 글자 |
| A-302 결재 | `승인하기` 버튼 | 없음 |
| A-102 직원 | `저장하기` 버튼 | 없음 |

## 8. 웹에서만 필요한 것

모바일에 없던 상호작용이라 규칙이 새로 필요하다.

- **포커스 링** — `colors.focusRing` 2px 아웃라인, 2px 간격.
  `:focus-visible`에만 준다. 마우스 클릭에는 안 나온다.
  **`outline: none`을 쓰지 않는다.** 관리팀은 하루 종일 키보드로 입력한다
- **hover** — 표 행과 누를 수 있는 것에만. 배경 `divider`
- **커서** — 누를 수 있으면 `pointer`
- 표 정렬(열 머리 클릭)은 **서버가 지원하는 열에만** 넣는다. 앱에서 정렬하지 않는다.
  목록이 페이지로 잘려 오므로 화면에서 정렬하면 그 페이지 안에서만 정렬된다

## 9. 확정된 결정 (2026-08-26)

초안에서 비워두었던 4건이다. 기준은 디자인 취향이 아니라 **운영과 사용성**이다.

| # | 항목 | 결정 | 기준 |
|---|---|---|---|
| 1 | 되돌릴 수 없는 동작의 `disabled` | **허용** | 실행 불가능한 상태를 미리 알린다 |
| 2 | `danger` 버튼 | **사용** | 비가역·중대 동작에만 |
| 3 | 포커스 링 | **토큰 추가** (`colors.focusRing`) | 키보드 사용성과 일관성 |
| 4 | 토큰에 없던 값 | **반복되는 것만 추가** | `tight`(8) · `rowHeight`(44) · `sideNavWidth`(200) |

각각의 규칙은 앞 장에 적혀 있다 — 1은 1장, 2는 5장, 3은 8장, 4는 `DESIGN_SYSTEM.md` 3장.

### 남긴 근거

**1번은 모바일 규칙과 갈린다.** `DESIGN_SYSTEM.md` 5장은 "`disabled` prop은 존재하지 않는다"고
못박고 있다. 관리팀 화면만 예외로 두는 근거는 **상태 의존성**이다 — 마감된 기간, 퇴사한 직원처럼
사용자가 고칠 수 없는 상태가 동작 가능 여부를 결정한다. 값이 틀린 것과는 다른 문제다.

예외를 좁게 유지하려고 조건 둘을 붙였다 (1장). 이유를 적지 않거나 서버 검증이 없으면
`disabled`를 쓰지 않는다.

**4번에 기준을 같이 뒀다.** 숫자를 전부 토큰으로 올리지 않는다. 두 번째로 쓰이는 순간 올린다.
`tight`(8)는 이미 모바일에서 `TextField`·`LeaveBalanceSection`·화면 넷이 각자 적고 있던 값이라
올릴 때가 지나 있었다.

- 인쇄·엑셀 내보내기 — 요구사항에 없다

## 11. 글자 위계와 화면 구조 (2026-08-31 확정)

시안 넷을 놓고 고른 결과다. `DESIGN_RULES.md` 3장(타이포그래피)과 4장(레이아웃과 여백)이
비어 있어 화면마다 눈대중으로 만들고 있던 부분이다. **관리팀 화면에 한해 여기서 확정한다** —
모바일은 그 두 장이 여전히 비어 있다.

### 글자

| 쓰임 | 토큰 | 값 | 색 |
|---|---|---|---|
| 화면 제목 | `pageTitle` | 26 / 34 / 600 | `textStrong` |
| 제목 아래 설명 (`.page-lead`) | `lead` | 14 / 22 / 400 | `textWeak` |
| 섹션 제목 | `sectionTitle` | 16 / 24 / 500 | `textStrong` |
| 표 본문 | `bodySmall` | 15 / 23 / 400 | `textStrong` |
| 표 헤더 | `label` | 13 / 20 / 400 | `textWeak` |
| 요약 값 | `headline` | 22 / 30 / 600 | `textStrong` |
| 요약 라벨 | `caption` | 12 / 18 / 400 | `textWeak` |

`pageTitle`과 `lead`를 토큰에 새로 넣었다. 관리팀 화면 전부가 쓰므로 9장 4번 기준(반복되는
것만 올린다)을 넘는다. **모바일은 제목에 `headline`(22)을 그대로 쓴다** — 웹은 좌측 메뉴·도구줄·
표가 한 화면에 같이 있어서 22로는 제목이 표 헤더에 묻힌다.

### 여백

| 쓰임 | 토큰 | 값 |
|---|---|---|
| 본문 상하 패딩 | `mainPadY` | 36 |
| 본문 좌우 패딩 | `mainPadX` | 32 |
| 블록 사이 (제목 ↔ 요약 ↔ 표) | `blockGap` | 24 |
| 표 행 최소 높이 | `tableRowHeight` | 48 |
| 표 헤더 높이 | `rowHeight` | 44 |

**본문(`.shell-main`)에 여백이 아예 없었다.** 스타일이 한 줄도 없어서 화면이 좌측 메뉴에
붙어 있었다 (2026-08-31 확인). 이것이 화면이 엉성해 보이던 가장 큰 원인이다.

### 읽는 너비 — 2장과 충돌하지 않는다

2장은 **"본문에 최대 너비를 두지 않는다"**고 정하고 있다. 20열짜리 급여대장을 좁은 칸에
넣지 않기 위한 규칙이고 그대로 둔다.

**최대 너비는 읽는 문장에만 건다** — `readWidth`(620), `.page-lead`와 요약 상자의 안내문.
표는 폭을 전부 쓴다. 한 줄이 화면 폭만큼 길면 눈이 다음 줄 첫 글자를 못 찾는데, 그건
표가 아니라 문장의 문제다.

### 화면 뼈대

```
제목 + 설명 ────────────────── 주 동작 버튼 (오른쪽 끝)
요약 줄            (있는 화면만)
┌──────────────────────────────┐
│ 도구줄 — 연도·기간·검색어      │
├──────────────────────────────┤
│ 표                            │
└──────────────────────────────┘
```

- **주 동작은 제목 줄 오른쪽 끝**에 둔다 (`등록하기`·`계산 실행하기`). 도구줄에 섞지 않는다 —
  거르는 것과 실행하는 것은 무게가 다르다
- **도구줄은 표와 한 상자에 넣는다** (`Table`의 `toolbar`). 무엇을 거른 표인지가 표에
  붙어 있어야 읽힌다
- **표를 상자에 담는다.** `border` 1px `border` · `radius` `chip`. 그림자가 아니라 테두리다 —
  `Dialog`·`SkippedNotice`·`GenerateResultNotice`가 이미 쓰던 모양이고 새 스타일이 아니다

### 요약 줄 (`Summary`)

표를 읽기 전에 알아야 하는 값을 표 위에 둔다. 공휴일의 `등록된 날 15일`처럼 **표를 세어야
알 수 있는데 그것이 화면의 목적인 값**이 여기 온다.

- **채울 값이 없으면 쓰지 않는다.** 보험 요율처럼 조회만 하는 화면에 숫자를 만들어 넣지 않는다
- 값은 서버가 준 것이거나 목록의 길이다. **여기서 업무 계산을 하지 않는다** (`CLAUDE.md` 3장)
- 그린을 쓰지 않는다. 예산은 주 동작 버튼과 `확정`류 상태 글자에 남겨둔다
