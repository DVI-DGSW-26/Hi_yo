## 0. 인증 — 거의 풀렸다 (2026-09-01 서버 답)

서버가 「HRM 로그인 붙이기」로 답을 줬고, **우리가 물어본 다섯 중 넷이 없어졌다.**

**방식이 우리가 생각한 것과 달랐다.** 프런트가 Keycloak과 직접 말하는 것이 아니라
**서버가 로그인을 중계하고 프런트에는 토큰만 넘긴다.** 그래서 —

| 물어봤던 것 | 답 |
|---|---|
| 프런트용 public client 등록 | **필요 없다.** 서버가 Keycloak과 직접 로그인한다. PKCE도 OIDC 라이브러리도 필요 없다 |
| 관리팀 콜백 등록 | **이미 돼 있다.** `/auth/callback`을 `localhost` 5173·3000과 `127.0.0.1` 네 조합으로 열어 뒀다 |
| 커스텀 스킴 리다이렉트가 되는지 | **된다. 등록만 하면 된다** — 아래 남은 것 참고 |
| 테스트 계정 Keycloak 아이디 | 우리가 가입하고 알려주면 된다 — 아래 남은 것 참고 |

**우리 코드는 거의 맞아 있었다.** fragment(`#token=`)로 받는 것, `sessionStorage`에 두고
`localStorage`를 피하는 것, `Authorization: Bearer`, `/auth/me`로 권한을 받는 것,
401 재이동을 한 번으로 막는 것까지 전부 서버 안내와 같다.

**고친 것은 둘이다** (2026-09-01).

- 로그인 입구를 `oauth2/authorization/keycloak` → **`/auth/login`**으로 바꿨다.
  둘 다 살아 있지만 `redirect`를 받는 쪽은 `/auth/login`뿐이다
- **모바일이 `redirect`를 안 싣고 있었다.** `callbackUrl()`을 만들어 두고 `loginUrl()`에
  붙이지 않아서, 등록이 끝나도 **토큰이 앱으로 오지 않을 코드였다.** 진짜 버그였다

### 실제로 끝까지 돌려봤다 (2026-09-01)

**앱 쪽 배선은 확인됐다.** 로그인 버튼 → Keycloak 로그인 → OTP → 서버가
`localhost:5173/auth/callback` 으로 정확히 돌려보내는 데까지 실제로 통과했다.

거기서 **토큰 대신 `#error=` 가 왔다.** 화면에 뜬 문구는 우리가 만든 것이 아니라
서버가 보낸 값을 그대로 보여준 것이다 — `로그인하지 못했습니다. 관리자에게 문의하세요.`

| 단계 | 결과 |
|---|---|
| 회원가입 · 비밀번호 | **통과** |
| OTP 등록 (Keycloak이 필수로 걸어 뒀다) | **통과** |
| 콜백 도달 (`#error=` 를 우리 화면이 받아 그림) | **통과** |
| 그룹 배정 · 인사 정보 연결 | **여기서 막혔다** |

**어느 쪽인지는 응답으로 구분되지 않는다.** 서버 문서가 그렇게 적고 있고 이유는 서버
로그에만 남는다 — 아이디를 알려주면 서버가 어디서 끊겼는지 봐 준다.

**OTP 등록이 필수라는 것은 문서에 없던 것이다.** 뒤에 가입할 사람도 같은 화면을 만난다.
앱 항목이 여러 개 쌓이면 옛 코드를 넣게 되므로, 다시 등록할 때는 인증기 앱의 옛 항목을
지우고 새 QR로 받는다.

### 서버에 보낼 것 (2026-09-02)

**서버가 다시 떴다.** 이날 오전에는 `api.dvi-ind.com` 이 **502**였다 (nginx). 지금은
`GET /v3/api-docs` 가 200이고 나머지는 전부 401이다 — 로그인만 남은 원래 상태로 돌아왔다.

**새로 묻는 것은 12번 하나다. 아래 문장 그대로 보내면 된다.**

> 연차 신청을 직원이 폰으로 내게 하려고 하는데, **신청서에 신청인 서명을 붙일 자리가
> 없습니다.** `LeaveRequestCreateRequest` 가 `typeCode` · `startDate` · `endDate` ·
> `startTime` · `endTime` · `reason` · `emergencyContact` 일곱 개뿐이고,
> `signatureMethod` · `signatureImage` 는 `RequestDecisionRequest`(결재)에만 있습니다.
> 응답의 `signed` 도 결재자 서명 여부로 보입니다.
>
> 회사 「휴가(근태)신청서」 양식에 신청인 서명란이 있다면 **폰으로 신청을 끝낼 수
> 없습니다.** `POST /requests` 에도 `signatureMethod` · `signatureImage` 를 받아주실 수
> 있을까요? 결재와 같은 형식이면 됩니다.

**13·14번은 재촉이다. 8-31에 넘긴 실측값에 대한 답이 아직 없다.**

> 8-31에 드린 서명 크기 실측(보통 서명 base64 31KB, 최악 72KB)에 대해 **상한을

| 18 | **근태 확정을 되돌릴 수 있는가** | `POST /attendance/judge?confirm=true`로 확정하면 그 날이 급여 계산에 들어간다. **되돌리는 경로가 스펙에 없다** — 잘못 확정했을 때 어떻게 하는지 모른다. 화면은 확인 대화상자에 "되돌리는 경로가 없다"고 그대로 적어 뒀다 |
| 19 | **요율이 없는 해를 계산하면** | 등록된 해가 2026년 하나뿐이다. 막히는지 0원으로 도는지 |
| 20 | **직군에 따라 지각·조퇴·외출을 다르게 공제하는가** | 회사 근태 시트가 **관리직은 표시만, 생산직(시급)은 30분 단위로 공제**한다고 적고 있다 (`API_근태.md` 8장). 서버가 이 구분을 하고 있는지 스펙에 없다 — 화면 문구가 갈린다 | **2026-09-02 확인** |

### 제안 — 지금 되지만 이렇게 해주면 낫다

| # | 무엇 | 왜 |
|---|---|---|
| 21 | **반차 시각을 `RequestTypeResponse`에 실어달라** | 지금은 앱이 `09:00`·`13:00`·`18:00`을 갖고 있다. 회사가 시각을 바꾸면 **앱을 다시 배포해야 한다.** 종류 응답이 이미 `halfDay`를 주고 있으니 시각도 거기 실으면 된다. **외출·조퇴는 자유 입력이라 이 요청과 무관하다** |
| 22 | **본인 급여 목록에서 확정 안 된 건을 빼달라** | 확정되지 않은 급여는 직원에게 안 보이기로 했다 (2026-09-01). 지금은 서버가 다 주고 화면이 거른다 — **금액이 기기까지는 온다.** 목록에서 빼주거나 필터를 달면 그럴 일이 없다 |
| 23 | **연차 자동 부여를 켜달라** | 자동 계산을 안 하는 이유로 "입사 첫 해 규칙이 확정되지 않았다"를 들었는데 **그 규칙이 확정됐다** (입사일 기준·근로기준법). 재직 46명에게 매월 월차를 손으로 넣는 것은 빠뜨리기 쉽고, 빠뜨리면 그 사람은 연차가 없는 채로 지나간다 |

## 3. 인사팀

| # | 무엇 | 막히는 것 |

| 1 | ~~연차 발생 규칙~~ | **풀렸다 (2026-09-01). 입사일 기준 · 근로기준법 그대로** — 1년 미만은 개근한 달마다 1일(최대 11일), 1년차부터 15일, 3년차부터 2년마다 +1일(최대 25일). A-306은 이제 서버 5번만 남았다 |

**인사팀 몫이 다 끝났다 (2026-09-01).** 여섯 중 다섯은 답을 받았고, 연차촉진은
**서버로 넘어갔다** — 조건이 없어서가 아니라 API가 아예 없어서다 (서버 11번).

4·5·6은 지금 동작이 맞다는 답이라 고칠 것이 없었고, 1번은 값이 정해져 **A-306이 서버
5번 하나만 남았고**, 2번으로 **S-301 반차 신청을 붙였다.**

**남은 것은 아래 공휴일 입력 하나다.**

**특별휴가(경조사) 일수표는 받지 않아도 된다.** 특별휴가는 발생(grant)이 아니라 신청이고,
연차를 깎지 않는다 (`deductLeave` 없음). 며칠인지는 서버·인사팀이 판단할 값이라
**앱이 알 필요가 없다.**

### 급한 것 — 공휴일 입력

**확인이 아니라 입력이 필요한 항목이다.** 연차 차감이 서버의 공휴일 목록을 보기 때문에,
등록되지 않은 날은 근무일로 계산돼 **연휴가 연차에서 깎인다.**

2026-08-31에 설날·추석 6일을 넣었으나 그 뒤 시드가 다시 심어졌다. 인증이 풀리는 대로
`GET /holidays?year=2026`으로 **살아 있는지 먼저 확인하고**, 부처님오신날·대체공휴일이
빠져 있으면 같이 넣어야 한다. 음력과 대체공휴일 규칙은 문서에 없어 **화면이 대신
판정하지 않는다** — 사람이 달력을 보고 넣는다.
