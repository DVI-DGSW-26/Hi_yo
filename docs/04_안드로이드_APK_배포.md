# 안드로이드 — APK 직접 배포

**정해졌다 (2026-09-10).** Play 스토어를 쓰지 않고 APK 링크로 직접 배포한다.
개발자 등록비를 쓰지 않기로 했다.

iOS는 별개다 — Apple 개발자 계정이 결제되지 않아 막혀 있다. `03_앱이냐_웹이냐.docx`를 본다.

---

## 이 방식의 대가와 대책

| 대가 | 대책 |
|---|---|
| 자동 업데이트가 없다 | **EAS Update(OTA)를 켰다.** 화면·문구·로직은 앱이 스스로 받아온다. 재설치는 네이티브가 바뀔 때만이다 |
| 「알 수 없는 출처」를 직원이 직접 허용해야 한다 | 첫 설치 때 한 번뿐이다. 아래 안내문을 그대로 보낸다 |
| 내려받기 링크가 영구하지 않다 | EAS 아티팩트 주소는 만료된다. 내려받아 사내 드라이브에 올리고 **그 주소**를 공지한다 |
| 설치 수·크래시 집계가 없다 | 지금은 없이 간다 |

## 설정한 것 (2026-09-10)

### `apps/mobile/app.json`

- `runtimeVersion: { "policy": "fingerprint" }` — 네이티브 구성이 바뀌면 값이 저절로 달라진다.
  구버전 앱이 맞지 않는 업데이트를 받아 깨지는 것을 막는 안전장치다.
- `updates.url` — 이 프로젝트의 OTA 주소.
- `fallbackToCacheTimeout: 0` — 켤 때 기다리지 않는다. 업데이트는 뒤에서 받고
  **다음에 앱을 켤 때** 반영된다. 즉 직원이 고친 내용을 보려면 한 번 껐다 켜야 한다.

### `apps/mobile/eas.json` — `production` 프로필

- `android.buildType: "apk"` — 스토어용 AAB가 아니라 APK를 뽑는다.
- `autoIncrement: true` — versionCode를 올린다. **이게 없으면 덮어 설치가 안 된다.**
- `environment: "production"`

## 절차

### 새 APK 내보내기 — 네이티브가 바뀌었을 때

```
cd apps/mobile
eas build -p android --profile production
```

### 화면·문구만 고쳤을 때 — 재설치 없이

```
cd apps/mobile
eas update --channel production -m "무엇을 고쳤는지"
```

### 어느 쪽인지 가르는 기준

**새 APK가 필요하다:** 네이티브가 딸린 라이브러리 추가·제거 · Expo SDK 올림 ·
`app.json`의 `plugins`·권한·`scheme`·`package` 변경 · 아이콘·스플래시 교체.

**그 외는 OTA로 간다:** 화면, 문구, 계산 없는 표시 로직, 스타일.

헷갈릴 일은 적다. `fingerprint` 정책이라 네이티브가 바뀌면 runtimeVersion이 저절로
달라지고, 그러면 구버전 앱은 새 OTA를 **받지 않는다.** 업데이트를 올렸는데 아무도
못 받고 있으면 네이티브가 바뀐 것이니 APK를 다시 돌린다.

배포 스위치를 켜기 전에 풀려야 하는 것들이다. 근거는 `01_물어볼_것.md`에 있다.

- **일반 직원 계정으로 권한 검증이 끝나지 않았다.** 지금 계정이 전부 관리팀이라
  남의 급여·주민번호가 보이는 것이 정상이어서, 안 보여야 할 것이 안 보이는지를
  증명하지 못한 상태다. 급여·주민번호를 다루는 앱에서 이건 건너뛸 수 없다.

  Keycloak 직접 전환 때 전원 재설치다. **이건 OTA로 못 넘긴다.**
- **연차 발생 기준(B)이 미정**이라 자동부여를 못 켰다. 직원이 보는 잔여일수가 맞지 않는다.
- **실기기 확인이 안 끝났다** — 글꼴 최대에서 급여명세서 금액이 잘리는지.
