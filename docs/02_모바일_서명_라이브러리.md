# 모바일 서명 — 라이브러리를 하나 더해야 한다

**사람이 정할 것이 하나 있다.** `CLAUDE.md` 7장이 라이브러리를 임의로 더하지 말라고 하고,
1장 3번이 새 컴포넌트를 만들기 전에 물으라고 한다. 이 문서가 그 질문이다.

정리 2026-09-02.

## 왜 필요한가

서명을 받아야 하는 자리가 셋이다.

| # | 어디 | 근거 |
|---|---|---|
| 1 | 직원이 내는 연차 신청서 | 회사 「휴가(근태)신청서」 결재란 (`API_신청결재.md` 5장) |
| 2 | 연차사용계획서 | 서식에 **「제출자 : ______ (서명 또는 인)」** (`API_연차.md` 10장) |
| 3 | 단체연차 | 종이로는 개인별 신청서로 받는다 (`API_연차.md` 8장) |

**관리팀 결재 화면에는 이미 만들었다** — `apps/admin/src/components/SignaturePad.tsx`.
웹이라 `<canvas>` 하나로 됐고 라이브러리를 쓰지 않았다.

**모바일은 그 방법이 없다.** React Native 에는 캔버스가 없다. 그리는 것도, 그린 것을
**base64 PNG 로 굽는 것도** 라이브러리가 있어야 한다. 서버가 받는 것이 base64 문자열이라
(2026-08-31 답변) **그림을 이미지로 굽지 못하면 아무것도 보낼 수 없다.**

**라이브러리 없이 되는 데까지는 이렇다** — `PanResponder` 로 손가락 좌표는 받을 수 있고,
작은 `View` 를 잇대어 선처럼 보이게 할 수도 있다. **거기서 끝이다.** 화면에 그려진 것을
이미지로 만드는 방법이 RN 자체에는 없다.

## 후보 넷

넷 다 **Expo SDK 57 이 공식으로 버전을 물고 있다** (`expo/bundledNativeModules.json`).
그 버전으로 넣으면 SDK 와 어긋나지 않는다.

| 후보 | SDK 57 이 무는 버전 | 최신판 |
|---|---|---|
| `react-native-webview` | **13.16.1** | 14.0.1 (2026-06-20) |
| `@shopify/react-native-skia` | **2.6.2** | 2.11.2 (2026-09-01) |
| `react-native-svg` | **15.15.4** | 15.15.5 (2026-05-11) |
| `react-native-view-shot` | **5.1.0** | 5.1.1 (2026-06-20) |

### A. WebView 안에서 지금 만든 캔버스를 그대로 쓴다 — 하나

`react-native-webview` 하나만 더한다. 관리팀에 이미 만들어 둔 캔버스 코드를 HTML 로
넣고, 다 그리면 `postMessage` 로 base64 를 꺼낸다.

- **관리팀과 결과가 같다.** 크기 상한 128KB, 백킹스토어 2배 고정, `data:` 앞머리 떼기 —
  실측까지 끝낸 그 코드를 두 번 만들지 않는다
- 라이브러리 **하나**, 네이티브 그리기 코드 없음
- 단점 — 서명칸이 앱이 아니라 **웹 조각**이다. 시스템 글꼴 확대·접근성 설정이 그 안에는
  닿지 않는다. 서명칸은 글자가 거의 없어 영향이 작지만, 원칙과는 어긋난다

### B. Skia — 하나

`@shopify/react-native-skia` 하나로 그리기와 굽기가 다 된다
(`makeImageSnapshot()` → base64). 그림 품질이 가장 좋고 크기·배율을 정확히 잡는다.

- 라이브러리 **하나**, 네이티브 그대로라 접근성·글꼴 설정이 앱과 같이 논다
- 단점 — **앱 바이너리가 커진다.** Skia 엔진이 통째로 들어간다.
  서명 하나 때문에 넣기에는 무겁다. 앱에서 Skia 를 쓸 다른 자리가 생긴다면 값이 달라진다

### C. SVG + 화면 캡처 — 둘

`react-native-svg` 로 선을 그리고 `react-native-view-shot` 으로 그 뷰를 PNG base64 로
캡처한다. RN 에서 오래 쓰여 온 조합이다.

- 부품이 흔하고 예제가 많다
- 단점 — **라이브러리가 둘**이다. 그리고 캡처는 화면에 보이는 것을 찍는 것이라
  배율을 우리가 고정해야 한다(관리팀에서 DPR 2 로 묶은 것과 같은 일).
  `view-shot` 은 손이 뜸한 편이라 SDK 가 오를 때 먼저 걸릴 수 있다

### D. `expo-gl` 로 직접 그린다

이미 깔려 있는 것으로 되기는 한다. **권하지 않는다** — 서명 한 칸 때문에 GL 코드를
쓰고 유지하는 값이 라이브러리 하나보다 비싸다.

## 추천 — A(WebView)

이유 셋이다.

1. **라이브러리 하나로 끝난다.** 규칙이 「임의로 더하지 않는다」이니 하나가 둘보다 낫다
2. **관리팀과 결과가 같아진다.** 서명은 두 앱이 같은 형식으로 서버에 보내야 하고,
   그 코드는 이미 만들어 실측까지 했다. 두 번 만들면 두 번 어긋난다
3. **가장 가볍다.** Skia 는 서명 하나에 엔진을 통째로 들이는 셈이다

**Skia 로 가도 괜찮다.** 앱 크기를 감수하고 「웹 조각을 앱에 넣지 않는다」를 더 중히 본다면
B 가 맞다. 그 경우 관리팀 코드와 별개로 한 번 더 만들고, **두 곳의 출력이 같은지**
(크기 상한·배경·앞머리) 확인하는 몫이 생긴다.

**C 는 둘을 더해야 해서 마지막이다.**
