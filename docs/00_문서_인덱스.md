## 서버에 알려야 할 것

### 재직증명서 단건·PDF에 권한 검증이 없다 (2026-08-26 확인)

Swagger는 `GET /certificates/{id}`를 "본인 것만 볼 수 있다"고 적고 있으나 **실제로는 막히지 않는다.**
개발 서버에 실호출한 결과다.

| 요청 | 결과 |
|---|---|
| `GET /certificates/1` — 발급자 본인 (`employee:2`) | `200` |
| `GET /certificates/1` — **다른 직원** (`employee:3`) | `200` — 남의 증명서가 그대로 나온다 |
| `GET /certificates/1/pdf` — **다른 직원** (`employee:3`) | `200` — PDF까지 받아진다 |
| `GET /certificates/1/pdf` — **인증 헤더 없음** | `200` — 그대로 받아진다 |
| `GET /certificates` (목록) — 다른 직원 | `200`, `totalElements=0` — 목록은 격리돼 있다 |

증명서에는 성명·부서·재직기간이 들어가고, 주민등록번호와 현주소도 등록되면 들어간다.
id가 `1`부터 순번이라 훑기도 쉽다. **목록만 막고 단건·PDF가 열려 있다.**

앱은 본인 id로만 호출하므로 이 구멍을 쓰지 않는다. 그러나 클라이언트가 막을 수 있는 문제가 아니다.
서버에서 요청자와 증명서 소유자를 대조해야 한다.

### `PUT /employees/{id}`가 전체 교체라 주민등록번호가 지워진다 (2026-08-26 확인)

**A-102 수정 화면을 만들 수 없는 이유다.**

`PUT /employees/{id}`는 보내지 않은 필드를 지운다. 개발 서버에 실호출해 확인했다.

```
사원001 원본        부서=임원, 직무=사무직
PUT (필수 3개만)    부서=null, 직무=null      ← 생략한 필드가 지워졌다
```

(확인 후 원래 값으로 되돌려 두었다.)

`EmployeeUpdateRequest`에는 `residentNo`가 들어 있다. 그런데 **주민등록번호는 어떤 조회
응답에도 담기지 않는다** — `EmployeeResponse`는 "어떤 경우에도 담지 않는다", `EmployeeDetailResponse`는
"재직증명서 출력 경로에서만 쓰이므로 여기에 담지 않는다"고 스펙에 적혀 있다.
화면이 받을 수 있는 것은 `residentNoRegistered` 불리언뿐이다.

**읽을 수 없는 값을 다시 보낼 방법이 없다.** 그래서 직원 정보를 한 번 수정할 때마다
주민등록번호가 지워진다. 그러면 그 직원은 재직증명서를 발급받지 못한다.

클라이언트가 막을 수 있는 문제가 아니다. 서버에서 둘 중 하나가 필요하다.

- `residentNo`가 없으면 **기존 값을 유지**한다 (부분 수정)
- 또는 주민등록번호 수정을 **별도 엔드포인트로 분리**한다 (계좌정보처럼)

그때까지 A-102는 등록·재직상태 변경·사번 부여만 만들었다. 인적사항 수정은 만들지 않았다.

### 개발 서버의 테스트 데이터 (2026-08-26)

화면을 실제로 돌려 확인하면서 만든 것들이다. **지우지 않는다** — 삭제 API가 없고,
직원·증명서는 설계상 지우지 않는 데이터다.

| 데이터 | 내용 |
|---|---|
| 직원 `id=38` | `테스트직원` / 사번 `TEST-038` / 개발·사무직 / **퇴사 처리해 둠** |
| 재직증명서 `id=1`, `id=2` | 용도 `앱 연동 테스트`, `확인` |
| 급여 기간 `id=1` | 2026년 8월. 마감 해제 상태 |

테스트직원은 **급여계산 대상이 아닌 직무(사무직)** 로 만들었다. 급여 계산 대상은 그대로 12명이다.
실제 명단과 섞이지 않게 퇴사 상태로 두었다.

### 주민등록번호 입력 경로가 화면 스펙에 없다 (2026-08-26)

명세서 A-102의 필드 목록에 주민등록번호가 없다. 그런데 재직증명서에는 들어가야 한다.
지금 화면으로는 등록할 방법이 없고, 개발 서버의 직원 37명 전원이 미등록 상태다.
어느 화면에서 누가 입력하는지 정해야 한다.

### 그 밖에 확인된 차이

- `POST /certificates`는 **201**을 준다. Swagger에는 200으로 선언돼 있다 (앱 동작에는 영향 없음).
- 값 검증 실패는 **400** `"요청 값이 올바르지 않습니다."`다. 업무 규칙 위반(422)과 다른 코드다 —
  앱의 오류 분기(`lib/apiError.ts`)는 이 구분을 그대로 따른다.
