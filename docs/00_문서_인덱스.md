## 확정된 것

### 플랫폼 분리 (명세서 7.1)
- **본인용 8개 화면(S-)** → `apps/mobile` (React Native / Expo)
- **관리팀용 17개 화면(A-)** → `apps/admin` (React 웹)
- 디자인 토큰은 양쪽 공유
- 배포는 사내 배포 원칙. 모바일은 MDM·TestFlight, **공개 앱스토어 등록 없음**

### 서버·클라이언트 역할 (명세서 7.2)

|---|---|
| 연차 발생·차감·잔여일수 | 계산 결과의 화면 표시 및 포맷 |
| 주 52시간 누적·임계 판정 | |
| 연장·야간·당직 수당 | |
| 4대보험 및 공제 | |

| 주민번호·계좌번호 마스킹 | |

**클라이언트는 재계산도 검산도 하지 않는다.**

### 데이터 형식 (명세서 7.2)

| 항목 | 서버가 주는 형식 | 화면 표기 |
|---|---|---|

## 미확정 — 확정 전까지 개발하지 않는다

명세서 8장에서 5건을 명시하고 있다.

| # | 항목 | 확정 주체 | 앱 영향 |
|---|---|---|---|
| 1 | 권한 체계 — 검토자·승인자가 독립 역할인지 관리팀 내 지정인지 | 인사팀 | 낮음 (앱은 제출까지) |
| 2 | 연차 발생 기준 — 회계기준 vs 입사일기준 | 인사팀 | 낮음 (서버 계산) |
| 3 | 소득세·지방소득세 항목 부재 | 인사팀 | 낮음 (서버 계산) |
| 4 | 연차촉진 조건 (대상 잔여일수·발송 시점·응답 기한) | 인사팀 | **S-302 막힘** |
| 5 | 화면 상세 스펙 — 25개 중 6개만 정의 | 기획 | **S-101/302/501/502/601 막힘** |

명세서가 "별도 문서로 관리한다"고 넘긴 것들 — 리포에 아직 없다.

- 계산 규칙 (연차 발생식, 52시간 산정 기준, 수당 배율, 4대보험 요율) → 서버 몫
- **인증 방식** → 앱에 직접 영향. `src/lib/api.ts` 인터셉터가 이것 때문에 비어 있다
- **전자서명 구현 방식** → S-301 제출, S-302 서명이 이것에 걸려 있다
- 코드값 체계
- 출력 문서 서식 (재직증명서 PDF)

### S-301 잔여연차 초과 신청 차단 (2026-08-24 확정)
