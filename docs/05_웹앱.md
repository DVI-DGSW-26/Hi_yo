# 웹앱 — 같은 앱을 브라우저로도 낸다

**만들었다 (2026-09-10).** iOS 실기기가 Apple 개발자 계정 때문에 막혀 있어서,
아이폰 쓰는 직원은 브라우저로 들어오게 한다.

`03_앱이냐_웹이냐.docx` 의 「웹으로 갈아타자」와는 **다른 이야기다.** 갈아타는 것이 아니라
**같은 코드를 웹으로도 내보내는 것**이다. 안드로이드는 그대로 APK 다 (`04_안드로이드_APK_배포.md`).

---

## 새 앱을 만들지 않았다

`apps/web` 을 따로 만들면 화면 15개를 두 벌로 관리하게 된다. 급여·주민번호를 다루는
앱에서 두 벌은 곧 **한쪽만 고쳐지는 것**이고, 그게 사고다.

대신 `react-native-web` 을 넣어 **지금 앱을 웹으로 내보낸다.** 화면 코드는 한 줄도
건드리지 않았다. 라우팅(`expo-router`)·상태(TanStack Query)·토큰(`@hr/tokens`)이
그대로 돈다.

### 늘어난 라이브러리 셋

`CLAUDE.md` 7장이 임의로 늘리지 말라고 해서 적어 둔다. 셋 다 Expo 가 웹을 낼 때 쓰는
공식 짝이고, **앱 번들에는 들어가지 않는다** (웹 번들에만 들어간다).

| | 왜 |
|---|---|
| `react-native-web` | React Native 컴포넌트를 DOM 으로 그린다. 이것이 핵심이다 |
| `react-dom` | 위가 요구한다 |
| `@expo/metro-runtime` | 웹 번들의 진입점 |

---

## 웹에서 다른 것은 네 자리뿐이다

Metro 가 **`.web.ts`·`.web.tsx` 파일이 있으면 웹 번들에서만 그것을 고른다.** 부르는 쪽은
그대로 두고 구현만 갈아끼웠다 — 내보내는 이름과 모양(`async` 포함)을 앱판과 똑같이 맞췄다.

| 자리 | 앱 | 웹 |
|---|---|---|
| `src/lib/auth` | `expo-secure-store` · 딥링크 | `sessionStorage` · 같은 탭 이동 |
| `src/components/SignaturePad` | `WebView` 안의 `<canvas>` | `<canvas>` 를 그냥 |
| `src/features/certificates/pdf` | 캐시에 받고 공유 시트 | blob 으로 받고 내려받기 |
| `src/features/auth/AuthGate` | — | 콜백을 읽는 자리가 다르다 (아래) |

### 토큰을 어디에 두나

**브라우저에는 `expo-secure-store` 가 없다.** `CLAUDE.md` 2장이 그것만 쓰라고 한 것은
기기 이야기이고, 웹에서 무엇을 쓸지는 **관리팀 화면이 이미 정해 뒀다** — `sessionStorage`,
막혀 있으면 메모리다. `localStorage` 를 쓰지 않는다: XSS 한 번에 털리고 탭을 닫으면
사라지는 편이 낫다. 같은 판단을 그대로 따랐다 (`apps/admin/src/lib/auth.ts`).

### 콜백을 읽는 자리 — **여기가 함정이었다**

`AuthGate` 는 `Linking.useURL()` 로 로그인 콜백을 읽는다. **웹에서는 이 훅만으로는
토큰을 잃는다.**

1. `useURL()` 은 첫 렌더에 `null` 을 주고, `getInitialURL()` **프로미스**가 풀린 뒤에 값을 준다
2. 그 사이에 `app/auth/callback.tsx` 의 `<Redirect href="/" />` 가 effect 에서 먼저 돈다
3. 프로미스가 풀릴 때 주소는 이미 `/` 다 — **`#token=` 이 없다**
4. 토큰을 영영 못 받고 **로그인이 무한히 돈다**

그래서 웹판은 **모듈이 뜰 때**(렌더보다 먼저) 주소를 붙들어 둔다(`pendingCallbackUrl()`).
다 쓰고 나면 `forgetCallbackUrl()` 이 주소창의 `#token=` 을 지운다 — 토큰이 주소창·
방문기록·referer 에 남지 않게 한다 (`CLAUDE.md` 2장).

**지우는 것을 모듈 로드 시점에 하면 안 된다.** 거기서 `replaceState` 를 불러 봤더니
뒤이어 뜨는 expo-router 가 원래 주소를 되돌려서 `#token=` 이 그대로 남았다
(2026-09-10 브라우저에서 확인). 라우터가 자리 잡은 뒤에 지워야 한다.

**앱 경로는 건드리지 않았다.** `pendingCallbackUrl()` 은 앱에서 `undefined` 를 돌려주고,
기기는 지금까지와 똑같이 `Linking.useURL()` 만 쓴다 — 2026-09-08 실기기에서 통과한
경로다.

## 빌드와 실행

```
cd apps/mobile
npx expo start --web            # 개발
npx expo export --platform web  # dist/ 에 나온다
```

나오는 것은 **`index.html` 하나 + JS 번들 하나**다 (`web.output: "single"`).

**`EXPO_PUBLIC_API_BASE_URL` 이 빌드 시점에 박힌다.** 주소가 바뀌면 다시 빌드해야 한다.
지금 값은 `https://api.dvi-ind.com/hi-yo` 다.

## 사내 서버에 올리기

**주소는 `https://hr.dvi-ind.com` 으로 정해졌다** (2026-09-10).

이 이름이 조건 셋을 다 만족한다 — 도메인 루트고, HTTPS 고, **`*.dvi-ind.com` 하위다.**
마지막이 중요하다: 갱신 쿠키가 `SameSite=Lax` 라 이 하위가 아니면 **토큰 갱신이 아예**
**안 된다** (`01_물어볼_것.md` 0장, 2026-09-08 서버).

> **DNS 를 다시 물려야 한다.** `hr.dvi-ind.com` 은 이미 있는 이름인데
> **회사 홈페이지(`dvi-ind.com` → `112.175.247.32`)로 가는 별칭**이다.
> API 서버(`112.146.55.77`)와도 다른 곳이다. 웹앱을 올릴 서버로 돌려놓아야 한다.

`dist/` 를 통째로 올리고 **정적 파일로 서빙**한다. 서버가 지켜야 할 것이 둘 있다.

### 1. 없는 경로는 `index.html` 로 돌려준다 (필수)

`/payroll/42` 같은 주소에 맞는 파일은 **없다.** 라우팅을 브라우저가 하기 때문이다.
그냥 올리면 앱 안에서 눌러 들어가는 것은 되는데 **새로고침하거나 링크로 바로 열면 404** 다.
급여명세서·재직증명서·당직 교체가 전부 그런 주소다.

```nginx
server {
  listen 443 ssl;
  server_name  hr.dvi-ind.com;

  root /var/www/hr-web;   # dist/ 를 올린 곳

  # 파일명에 해시가 들어 있어 오래 캐시해도 된다
  location /_expo/ {
    try_files $uri =404;
    expires 1y;
    add_header Cache-Control "public, immutable";
  }

  # 나머지는 전부 index.html — 이 한 줄이 위의 404 를 막는다
  location / {
    try_files $uri /index.html;
    add_header Cache-Control "no-cache";   # 새로 올린 것이 바로 보여야 한다
  }
}
```

Apache 면 `FallbackResource /index.html` 한 줄이 같은 일을 한다.

### 2. 도메인 루트에 올린다

`index.html` 이 자산을 `/_expo/...` 로 **루트 절대경로**로 부른다.
`https://<서버>/hr-app/` 같은 **하위 경로에 올리면 통째로 깨진다.**

하위 경로에 올려야 한다면 `app.json` 에 `experiments.baseUrl` 을 넣고 **다시 빌드**해야
한다. 지금은 넣지 않았다 — 어디에 올릴지 정해지면 그때 넣는다.

### 3. 서버가 이 오리진을 CORS 로 열어줘야 한다

웹앱(`hr.dvi-ind.com`)과 API(`api.dvi-ind.com`)는 **다른 오리진**이다. 브라우저가
막으면 로그인은 되는데 **화면마다 데이터가 하나도 안 뜬다.**

2026-09-10에 실제로 찔러 봤다 — **화이트리스트 방식이고 지금은 개발용만 열려 있다.**

| 오리진 | preflight |
|---|---|
| `http://localhost:5173` | **200** · `Access-Control-Allow-Origin` 돌아옴 |
| `https://hr.dvi-ind.com` | **403** |
| `https://dvi-ind.com` | **403** |

**서버에 등록을 요청해야 한다** (`01_물어볼_것.md` 0.5). `Authorization` 헤더를 쓰므로
허용 헤더에도 들어가야 한다.

### 그리고 HTTPS 여야 한다

Keycloak 이 돌려보내는 주소이고, 토큰이 오간다. 사내망이라도 평문 HTTP 로 두지 않는다.

## 덤 — 모바일 화면을 브라우저로 볼 수 있게 됐다

지금까지 모바일 화면은 `react-native-web` 이 없어 브라우저로 못 돌렸고, 그래서 확인할
길이 APK 실기기뿐이었다. 이제 관리팀 화면처럼 브라우저로 실데이터를 보며 확인할 수 있다.
**글꼴 확대 시 레이아웃이 깨지는지도 브라우저에서 먼저 걸러진다** — 실기기에서만 보이는
것(딥링크·스킴·라우팅)은 여전히 실기기로 봐야 한다.
